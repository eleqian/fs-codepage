# 2026-09-30

## 老固件（10.0.0 / 11.0.1 / 12.1.0 / 13.2.1）兼容性分析

固件目录新增 4 个老版本，做了完整的静态可行性评估，**未改 `fs_codepage.cpp`**。
结论写在 `doc/old-fw-compat.md`（已加进 `doc/README.md` 索引）。

### 结论
- 现表直命中（14 族）：13.2.1 = 12、12.1.0 = 11、11.0.1 = 4、10.0.0 = 4（0819/081b 一致）。
- **无硬阻塞**：洞够、收割成、ctx/对象布局一致。
- 13.2.1 只需改 3 条 pattern；12.1.0 再加 1 条；10/11 是另一代代码生成，需 8 条新变体
  （10.0.0 与 11.0.1 共用）。补齐后四版都是 14/14，条目 31 → 39，族数仍 14。
- 唯一要动守卫：`str_unicode2oem` 的跨版本最小洞 0x120 → **0x110**（10/11 实测），仍 > 0xEC。

### 修掉两个会静默骗人的工具 bug（重要）
1. `scripts/fs_fw_audit.py::parse_fs_pattern` 按「一个 `.` = 一槽」解析，与 `str2hex`
   差一倍槽数 ⇒ 带通配符的 24/31 条被误报 0 命中（连 14.1.2 自己都只命中 4 条）。已按
   `..` = 一字节改正，并同步修正 `MEMORY.md` 里那条写反了的约定。
2. `audit_at` 没把 `--base-fs` 传给 `parse_sites` ⇒ 换基线只影响重定位、不影响取点，
   永远只扫到 19.0.1 那 7 条。已修。
   自检：14.1.2 / 19.0.1 各自 14/14 唯一命中。

### 新增工具
- 入库：`scripts/fs_pat_hits.py`（逐份数 31 条命中数 + `--try` 验候选 pattern 全语料唯一性）。
- 临时（`D:/Game/NS/firmware/_audit/`）：`_oldfw_probe.py` / `_oldfw_matrix.py` /
  `_harvest_check.py` / `_holes.py` / `_extent.py` / `_mkpat.py` /
  `_ghidra_scripts/FuncDump.java`。

### 方法沉淀（下次评估新固件照这个顺序）
1. `fs_pat_hits.py --dir` 出命中矩阵 → 看哪些族缺。
2. 缺的族：以**最接近的已知版本**为基线（`--base-fs`）做锚点重定位拿候选落点。
3. 候选落点上跑 `_harvest_check.py`（收割）+ Ghidra `FuncDump.java` 出洞（转换器类叶子
   函数 Ghidra 认不出，改用「原函数自身长度」当保守下界）。
4. 新 pattern 用「两版本逐指令共识（一致写死/不一致整条通配）」生成，再用 `--try`
   在**全部语料**上验「0 或 1 次命中」（族间互斥是硬不变量）。
5. 别忘了族间重叠：放宽后的新变体可能和旧变体在同一版本上同时命中，必须先收紧旧的。

## 落地：支持下限 12.0.0 + 条目改按大版本命名（同日第二轮）

用户定口径：**补丁从 12.0.0 起支持；相同大版本 fs 驱动不变**。于是：

### 命名改口径
- 版本范围从 `14.1.2-15.0.1` / `16.1.0+` 改为**大版本**：`12-15` / `16+` / `12-14,21+` /
  `12`（单点）。依据即上面两条。旧写法在 `NAME_RE` 里仍兼容但不再用。
- 同步改了 4 处正则/注释：`fs_codepage.cpp` §4 表头 + 两张表的表头注释、
  `check_patch_sizes.py::NAME_RE`（`_VER_ITEM` 放宽为 `\d+(?:\.\d+\.\d+)?(?:-…)?\+?`）、
  `scripts/fs_fw_audit.py` 表头注释。族号提取（`fs_family_of` / `point_of`）不受影响
  （只看「第一个 `_`+数字」）。

### 让名字说实话（不改 pattern 就没法把 12/13 写进范围）
| 改动 | 内容 | 覆盖 |
|---|---|---|
| `str_getcharcount_12-15` | 第 26 字节 `41` → `..`（ctx 地址字节） | 12–15 |
| `widechar_compare_12-14` | 尾部 `..0C00D0` → 16 个通配 + 补 `F30303AAF40301AA` 锚 | 12–14 |
| `fat_getnextpathcomp_step_12-14` | 追加 `891B40F9` 消歧（原来 10/11/12 上是 **2 命中**） | 12–14 |
| `pfcode_oem2unicode_12`（新增） | `0x0800C0390A1D0012EB030A2A2803F836`，`entry_offset=0` | 12 |
| `pfcode_oem2unicode_16+` | 追加 `........20008052`（`mov w0,#1`）收紧 | 16–22 |

- 收紧 16+ 的那条**必须做**：原来那条 12 字节松散模板会**意外命中 12.1.0**（落点正确但
  名字说谎，且与新 `12` 条目族内冲突）。
- 表规模 31 → **32**（blob 16 → 17），`fs_fn_groups` 的 blob 区间改成 6–12 / 12–15 / 15–17，
  `static_assert` 同步。族仍 **14**。
- `make` 通过；7 个替换体尺寸/洞逐位不变，`str_unicode2oem` 洞仍 **0x120**
  （0x110 只出现在 10/11，已出支持范围 ⇒ 不必下调守卫）。
