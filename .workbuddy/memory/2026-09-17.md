## 2026-09-17 ARCHIVE 位问题的 fs 侧补丁方案（第七轮，re_bigdir_dir_as_file.md）
- 前提：用户已实测确认根因 = /Roms 顶层 25 个目录条目 attr=0x30（DIR|ARCHIVE），app 显示成文件、大小 0。
- ★ 两条出口不一致：`IDirectory_Read`@0x71000d4a20 输出 DirectoryEntry 时
  type@+0x304 = (attr&0x10)==0（**目录恒正确**），attributes@+0x301 = (attr>>4)&3（0x30→**3，非法值**），size@+0x308 目录恒 0。
  坏掉的只有 attributes；app 对它做 `==1` 严格比较才判目录 ⇒ 3 落进文件分支。
- ★ 关键约束（反直觉，勿踩）：fs **内部**以 v==3 为"目录" —— `fs_check_is_directory`@0x7100174efc
  `bics wzr,w9(3),w8` + `cset w20,eq`；`fs_check_not_directory`@0x7100175018 同判据。
  而 app/libnx 契约是 0=Dir/1=File，只有 v==1 才是目录。故**不可**直接归一化共享出口
  `fs_get_file_type_by_path`@0x71000d30e0（会连带让"禁止对目录做文件操作"的守卫失效）。
- 方案 A（推荐，零风险，1:1 原地改写、不需要代码洞）：只归一化枚举 attributes，位置 0xd4b6c/0xd4b7c/0xd4b8c：
  nop→`mov w9,#0x310`(09 62 80 52)；`mov w9,#0x310`→`ubfx w11,w8,#4,#2`(0B 15 04 53)；
  `ubfx w8,w8,#4,#2`→`csinc w8,w11,wzr,eq`(68 05 9F 1A)。
  复用未改动的 `tst w8,#0x10`(0xd4b88) 标志：Z=1(文件)→w8=v；Z=0(目录)→w8=1 ⇒ 0x10/0x30 目录统一为 1。
  已验证：csinc 不写 NZCV（后续 cset/csel 安全）、w11 空闲、该区间无任何分支跳入、与 0xd4af4 补丁点不冲突。
  36 字节整段：原 1F2003D5...08150453 / 新 09628052...68059F1A（全文见报告）。
- 方案 B（备选，有语义风险）：归一化 GetEntryType 需 5 条指令但只有 4 槽 → 需 trampoline（函数尾仅 8B padding），且会改变上述内部判定。仅当确认 app 走 GetEntryType 且 A 无效后再做。
- 方案 C（不推荐）：源头清 FsObject.dwAttr 的 A 位（0x71000f1140/0x71000fcc10），可能被写回磁盘。
- 集成建议：走 patches[] 表（fs title），单条目 36B 需把 PatchData::data[20] 扩到 ≥36；或拆 3 条目各 4B。加 config 开关 + fw 门控（偏移取自 19.x）。check_patch_sizes.py 目前只校验 fs_patch_function() 点，新增点建议纳入 --fs 比对 + pattern 唯一性检查。


## 2026-09-17 第八轮（用户问方案 C 是否更简单）—— ★ 推翻第七轮核心结论
- ★ 新发现：v==3 不只是显示错，fs **主动拒绝**。`fs_directory_open`@0x7100176664 反编译硬代码：
  `uVar2=fs_check_is_directory(); if ((uVar2&1)==0) 打开 else fs_log_error_code(0x202)`；
  `fs_check_is_directory`@0x7100174efc 返回 `(v&3)==3`；`fs_check_not_directory`@0x7100175018 同判据。
  **0x202 = 模块2(FS) 描述1 = "Path does not exist"**（switchbrew 错误码表）
  ⇒ attr 0x30 目录 OpenDirectory 直接 PathNotFound，Switch 上根本进不去；枚举能看到是因为枚举不走这两个 check。
- 修正：第七轮"fs 内部以 v==3 为目录"理解反了 —— v==3 是 fs **专门拒绝的非法值**（v==1 纯目录才放行）。
  故**方案 A（只改枚举显示字节）治标不治本**，目录仍打不开。
- 方案 C 评估（用户倾向）→ **不更简单**：① 陷阱：无差别清 A 位使文件 attr 0x20→0x00，
  经 `fat_init_fs_object_from_entry` 兜底 `dwAttr?dwAttr:0x40` → wAttr=0x40 → `type=(wAttr&0x10)==0`=**0=Directory**，
  文件全变目录；必须条件清位（+3 指令：and w8,w8,#0xffffffdf 121a7908 / tst w8,#0x10 / csel w8,w9,w8,ne 1a881128）。
  ② 空间都差 4 字节：FAT32 改点 0x71000f1140 可用 0x60 需 0x64；exFAT 0x71000fcc10 可用 0xA0 需 0xA4 → 必须 trampoline
  （.text 内 ≥16B 零洞仅 1 处：VA 0x71000000c4，60B）。③ dwAttr 有写回磁盘路径。
- **方案 G（新推荐，最简单）**：两处判据常量 `mov w9,#0x3` → `mov w9,#0x4`（0x7100174f38、0x71001750c4，
  原字节 `69 00 80 52` → `89 00 80 52`）。因 v∈{0..3} 恒无 bit2，`4 & ~v` 恒非 0 → Z 永 0 → check 永不拒绝。
  1:1、零代码洞、Rd 不变属守卫白名单。
- **建议组合 A+G**（共 5 条 1:1）：G 修"打不开"，A 修"显示为文件"（0xd4b6c/0xd4b7c/0xd4b8c）。可先只上 G 验证。
- 报告已追加第八轮；MEMORY.md 已重写精简（原文件超限被截断）。


## 固件兼容性审计工具落地（下午续）

**新增 `fs_encode_fix/fs_fw_audit.py`** —— 一条命令从固件包到"偏移还能不能用 + 新偏移是多少"。

- 解包链路自动化（按 `ns_reverse/cmd.txt`）：头扫描定位 BootImagePackage → cnmt → package2 →
  INI1 → `kip1 --uncompressed`。子命令 `unpack|check|audit|all|holes`。
- **三个坑（都曾造成误判，已内置处理）**：
  1. **NCA 头前 0x200 字节加密**（连 `NCA3` magic 都是密文）⇒ 纯字节扫描读不到 Title ID；
     必须 `hactool -i` 逐个问（~80ms/个，116 个约 10s，缓存 `cnmt_titles.json`）。
  2. **hactool 路径坑**：它把 `--romfsdir/--section0dir` 的值与文件名用 `\` 硬拼 ⇒ 传正斜杠得到
     `a/b
ame` 混合路径，fopen 静默失败、rc 仍为 0，只打一行 `Failed to open`；且**不创建 base 目录**。
     统一转反斜杠 + 预先 makedirs。nstool 相反，遇到混合分隔符直接报
     `Path literal has both forward and backward separators`。已收口到 `norm_tool_arg()`。
  3. **压缩态 KIP1 的头部与解压态逐字节相同**，只有文件长度不同 ⇒ 传错会让 29 点全报"失效"。
     判据：段表 `out_size` 超文件长度，或 sec0 `comp_size < out_size`（注意不能用"段大小总和 > 文件长度"，
     第 4 段 bss 只有大小没内容，会误报）。
- 定位算法：同址 → 精确唯一 → 锚点投票（±64 窗口按 4B 字投票）→ 块漂移印证（多轮把已定点 delta 回灌）。
- **语义归一化掩码修了三个真 bug**：原表注释写了 ADRP/CBNZ/TBNZ，掩码却只覆盖 ADR/CBZ/TBZ —
  - `CBZ/CBNZ` 用 `0x7F000000/0x34000000` ⇒ CBNZ(0x35) 匹配不上，改成 `0x7E000000/0x34000000`
  - `TBZ/TBNZ` 同理改成 `0x7E000000/0x36000000`
  - `ADR/ADRP` 只列了 `0x9F000000/0x10000000`（ADR）；ADRP 是 `0x90000000`，必须单独一条
  这个 bug 让 4 个本来正确的点被误报 FUZZY。
- 打分窗口改成三个变体 `(±16) / (0,+32) / (−32,0)` 取**最高**语义匹配率。原因：单一 ±64 宽窗会跨进相邻函数
  （相邻函数在新固件里改了）或本函数栈帧改版（`ldrb w8,[sp,#0x18]` 这类 imm12 变了），把不属于本点的差异算进来。
- `AMBIGUOUS` **不再当场冻结**（改成 `continue` 等下一轮）：cmp 字节重复时两个候选会同分同宽窗，
  但"该 delta 被多少已定位点共享"是可靠判据，所以留到后续轮次再判。例：`StringDesc_ToUpper` 就是靠 +19216 有 16 票定的。
- 新增硬指标 **`cmp 精确命中 N/29`**（`fs_patch_function()` 会逐字节比对 cmp，不命中整点跳过）——
  "定位看着对"不等于"能落地"。
- `holes` 子命令重推「洞」：**锚点定位基线里的边界函数入口**（`FUNC_HOLES` 新增 `boundary` 字段），
  比"扫下一个函数序言"的启发式可靠得多（转换器那类叶子函数没有栈序言 ⇒ 启发式高估；
  实测 0xFEC30 估成 0x370，真值 0x1D0）。边界定位不到时用「旧洞投影 + 边界首指令/填充特征校验」。
  顺带加了 ELF 符号读取（`elf_symbol_sizes`）算余量。

**19.0.1 实测结论：29/29 定位成功、0 需人工确认、0 失效、cmp 精确命中 29/29，5 个洞与基线完全一致。**
