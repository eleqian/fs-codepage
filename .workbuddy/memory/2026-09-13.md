## 第九轮：IDirectory 命令派发真相 + 误命名纠正 + PRF2SAFE + FUN 清扫（深夜）

**核心发现 — IDirectory 命令派发约定**：`fs_dispatch_method_cmd`(0x71000ce6a4) 以 `(*cmd->ppMethodSlot)(cmd)` 调用方法，**方法收到 FsMethodCmd* 而非 this**：{ppMethodSlot@0, out@8, arg@0x10}。命令槽 0x28 束 = [方法, nop桩, release, null, null]。槽：open_dir=0x71002474f0、close_dir=0x7100247548、open_directory=0x7100247570、fopen=0x7100247450；客户端 vptr=0x7100247518。

**5 个误命名纠正**（rename+prototype+plate 全改）：
1. fs_idirectory_open_file_by_path → **fs_idirectory_cmd_close_dir_handle**(0x71000d4d38)
2. fs_open_file_by_oem_path → **fs_close_file_handle**(0x7100116670)
3. fs_file_delete → **fs_file_set_size_transactional**(0x71001039c0, 事务内 ftruncate)
4. fs_file_delete_wrapper → **fs_file_set_size_wrapper**(0x7100116100)
5. fs_idirectory_get_entry_size/fs_get_entry_size_by_oem_path → **fs_idirectory_cmd_open_dir/fs_open_dir_by_oem_path**(0x71000d4934/0x71001165f0)

**fs_idirectory_create 第 3 参坐实 = 初始文件大小**（initialSize<0→0x2f7202，经 set_size_wrapper 传入）。

**FatDirSearchObject(0x28) 新结构**：opendir 真正返回的是 pDir_object_array(0x28 步长)里的目录搜索对象（不是 FatFileHandle！）：{status(in-use|0x80000000), flags, FatFileObj*@8, 搜索ctx@0x10, 位置@0x18..0x27}，存 FsDirIterObj+0x7a8（更名 pDirSearchObj；+0x7c8→ppOwnerFatCtx）。**前 0x28B 与 FatFileHandle 头部同构**，fs_close_file_by_context 池校验按 0x28 步长 = 此对象专用关闭路径。Ghidra+fs_structs.h 均已建。

**Prf2SafeCtx(0x10C) 新结构**：PRF2SAFE = 介质驱动层写前备份日志+恢复。恢复头 2 镜像扇区(magic/ver 100|0x65/槽号@0x16/错误码@0x20/FAT数@0x24/checksum@0x1fc)；9 槽日志表 {start,count}@0x30..0x74；recovery_operation_dispatch(0x7100113680)=15 操作码总派发（op0xc=日志回放）。经表 G +0x68/+0x78 槽间接调用。

**16 个 FUN_ 全部命名**（fs_fatwrapper_cleanup_rewind / fs_fatwrapper_recover_if_error / fs_map_volume_error_code 等），**FS 核心区 FUN_ 清零**。

**产出**：Ghidra 新结构 FsMethodCmd(0x18)/FatDirSearchObject(0x28)/Prf2SafeCtx(0x10C)，改原型 ~30 个、plate 注释 8 个、数据标签 2 个，save_program ×2；fs_structs.h（gcc 断言全过，注意 Prf2SafeCtx 需补 0x00/0x0c/0xfc 间隙字段）；re_analysis.md §1.11。

**遗留**：pPool_base(0x520 步长,+0x518) vs pFile_object_array(0x510 步长,+0x508) 双池并存待核；opendir 分配 0x7D0 但实际足迹 ≥0x7e0。
